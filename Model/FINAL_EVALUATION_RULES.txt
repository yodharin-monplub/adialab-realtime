IS A SELECTION NEEDED?  No.
  The glossary says code "or selection" is frozen in the out-of-sample phase, and
  every project has a `selected` attribute - but this competition has
  projectSelectionLimit = None, and `selected` is None on both our projects (as it
  is for everyone). There is nothing to select.
  The docs do not say whether the private run uses the LATEST or the BEST
  submission. On minimum-mantis Submission42 (#83777) is BOTH our latest and our
  best, so either rule picks it. Keep it that way: never upload anything weaker to
  minimum-mantis after it.

DUPLICATE PREDICTIONS - the one real trap
  Models whose predictions are > 95% Spearman-correlated, grouped by user AND by
  team, are paired; "the best model in a pair is always kept. Other models are
  treated as copies" and are INELIGIBLE FOR PRIZES. (The threshold can change at
  the organizers' discretion.)
  Today the leaderboard shows duplicate = False for both our projects, and the
  leader outscores sympathetic-trout (0.636670 vs 0.633111).
  DANGER: if sympathetic-trout ever held a correlated submission that scored
  HIGHER than the leader's, the LEADER would be the copy and lose eligibility.
  -> Do not upload to sympathetic-trout any more. It is not ranked anyway, so it
     can only ever hurt us. If a better model exists, it goes to minimum-mantis.
